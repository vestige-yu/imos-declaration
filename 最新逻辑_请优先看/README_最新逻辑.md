# 报关单生成项目 - 最新逻辑说明

## 先看哪些文件

当前最新逻辑只需要优先看本文件夹里的 3 份文件：

1. `报关单配置关系表.xlsx`
   - 给 exe 读取的配置关系表。
   - 作用类似“轻量配置数据库”。
   - 客户可以直接维护商品主数据、品牌/国家等值标准化和版本记录。
   - 字段解析、料号匹配、合并规则等结构性变化，需要同步更新程序，不能只改 Excel 说明文字。

2. `报关单生成取值逻辑说明.docx`
   - 说明报关单生成时数据怎么取。
   - 包括 Invoice 和 Packing list 怎么匹配、商品怎么合并、哪些字段留空。
   - 如果业务规则要改，先改这份说明，再同步更新配置关系表和应用。

3. `报关单配置关系表说明文档.docx`
   - 给业务人员/客户看的说明。
   - 解释配置关系表每个 Sheet 有什么用、为什么要维护、怎么维护。

## 当前最新核心规则

- 真实工作输入只有 `Invoice` 和 `Packing list`。
- `Daily / 商品主数据` 只作为关系查询表，不编辑源文件。
- 报关单模板只提供格式，不允许从旧报关单里读取业务数据。
- qty. 为空、0、- 的商品不进入报关单。
- Invoice 与 Packing list 先按标准化后的 `QAD P/N` 精确形式匹配；精确形式不存在时，才使用确认过的版本后缀候选键。
- 同一料号：忽略 `-`、`_`、`/`、`.` 分隔符；纯数字料号忽略首尾零；统一全角/半角并删除空白；纯数字 Excel `.0` 去除；数字或字母数字版本后缀可作为次级匹配。
- 不同料号：客户/品牌前缀不同、`O/0` 或 `I/1` 不同、无明确关系的新旧料号，不自动转换。
- Old Part No. 只有与 QAD P/N 在商品主数据同一行明确维护时，才作为已确认对应关系。
- 若同一候选键对应不同 HS code、中文品名或品牌，程序停止自动选择并提示人工确认。
- Invoice 只提供发票号、日期、客户、运输方式、成交方式、料号、数量、单价、总价、币制等交易数据。
- Packing list 提供重量、包装、托盘数/件数。
- Daily / 商品主数据是料号对应 HS code、中文品名、品牌的唯一来源。
- 运输方式按 Invoice 中运输字段标准化：Sea / SEA FCL / SEA LCL / Ocean / FCL / LCL 统一填“水路运输”；Air / DHL / FedEx / UPS / Express 统一填“航空运输”。
- 成交方式按 Invoice 的 Delivery Term 标准化：CPT 填 CPT，FOB 填 FOB，EXW 填 EXW。
- 境内发货人固定填写：凯斯库汽车部件（苏州）有限公司3205240783。
- 境内发货人代码固定填写：91320594762449680U。
- 包装种类固定填写：再生木托。
- 监管方式固定填写：一般。
- 征免性质固定填写：101。
- 离境口岸固定填写：上海。
- 商品行征免固定填写：照章征税。
- 商品合并时：
  - HS code 参与合并
  - 中文商品名称参与合并
  - 品牌参与合并
  - 币制参与合并
  - 最终目的国参与合并
  - 车型不参与合并
- 数量、总价、净重、毛重只做加总。
- 源文件没有的数据留空，除非配置表明确设置固定默认值。

## 文件夹说明

- `最新逻辑_请优先看`
  - 当前最新可用文档和配置表。

- `源文件_样例`
  - 用于测试和对照的源数据文件。
  - 包括 Daily、Invoice、Packing list、基础数据。

- `模板和生成结果`
  - 空白模板和按严格逻辑生成的样例报关单。

- `历史归档_旧版本`
  - 旧命名文件、中间版本、旧报关单样例。
  - 正常情况下不用看。

## 后续修改建议

如果业务规则变化，建议按这个顺序处理：

1. 先改 `报关单生成取值逻辑说明.docx`，明确业务结论。
2. 再同步修改 `报关单配置关系表.xlsx`。
3. 商品主数据和值标准化变化，重新上传配置表即可生效。
4. 字段解析、料号匹配、合并等结构性规则变化，必须同步修改并重新发布程序。
5. 用 `样例与测试资料` 跑回归测试，核对数量、金额、净重、毛重和商品主数据取值。
