# 报关单生成项目 - 最新逻辑说明

## 先看哪些文件

当前最新逻辑只需要优先看本文件夹里的 3 份文件：

1. `报关单配置关系表.xlsx`
   - 给 exe 读取的配置关系表。
   - 作用类似“轻量配置数据库”。
   - 后续客户维护字段、商品、品牌别名、合并规则时，主要改这张表。

2. `报关单生成取值逻辑说明.docx`
   - 说明报关单生成时数据怎么取。
   - 包括 Invoice 和 Packing list 怎么匹配、商品怎么合并、哪些字段留空。
   - 如果业务规则要改，先改这份说明，再同步更新配置关系表和应用。

3. `报关单配置关系表说明文档.docx`
   - 给业务人员/客户看的说明。
   - 解释配置关系表每个 Sheet 有什么用、为什么要维护、怎么维护。

## 当前最新核心规则

- 真实工作输入只有 `Invoice` 和 `Packing list`。
- `Daily / 商品主数据` 只作为关系查询表，不编辑源文件。
- 报关单模板只提供格式，不允许从旧报关单里读取业务数据。
- qty. 为空、0、- 的商品不进入报关单。
- Invoice 与 Packing list 优先用 `QAD PN / part_no` 匹配。
- Invoice 只提供发票号、日期、客户、运输方式、成交方式、料号、数量、单价、总价、币制等交易数据。
- Daily / 商品主数据是料号对应 HS code、中文品名、品牌的唯一来源。
- 商品合并时：
  - HS code 参与合并
  - 中文商品名称参与合并
  - 品牌参与合并
  - 币制参与合并
  - 最终目的国参与合并
  - 车型不参与合并
- 数量、总价、净重、毛重只做加总。
- 源文件没有的数据留空，除非配置表明确设置固定默认值。

## 文件夹说明

- `最新逻辑_请优先看`
  - 当前最新可用文档和配置表。

- `源文件_样例`
  - 用于测试和对照的源数据文件。
  - 包括 Daily、Invoice、Packing list、基础数据。

- `模板和生成结果`
  - 空白模板和按严格逻辑生成的样例报关单。

- `历史归档_旧版本`
  - 旧命名文件、中间版本、旧报关单样例。
  - 正常情况下不用看。

## 后续修改建议

如果业务规则变化，建议按这个顺序处理：

1. 先改 `报关单生成取值逻辑说明.docx`。
2. 再同步修改 `报关单配置关系表.xlsx`。
3. 如果 exe 已经按配置表读取，则一般不需要重新打包 exe。
4. 用 `源文件_样例` 跑一次测试，核对数量、金额、净重、毛重。
