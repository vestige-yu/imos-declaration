# 报表合并逻辑说明

## 目标

把最多 30 份结构类似于“测试表 1、2、3”的源报表纵向追加为一份报表，并按客户上传的输出模板决定字段顺序，按客户上传的规则文件补齐商品名称和商品编号。

应用部署为 Windows 本地程序，启动后只监听 `127.0.0.1`，用户通过本机浏览器操作，不把客户报表上传到外部服务器。

## 输入文件

- 源报表：`.xls` 或 `.xlsx`，一次 1～30 份。
- 输出模板：`.xlsx`。
- 规则文件：`.xlsx`。
- 不依赖固定工作表名或固定表头行。
- 源报表明细至少需要可识别的 `QAD PN/Part No.` 和 `Quantity/Qty` 列。
- 输出模板至少需要 `QAD PN/Part No.` 和另一个已支持字段。
- 规则文件至少需要 QAD PN/Part No. 与商品名称或商品编号的对应关系。

## 匹配键

唯一匹配键为 QAD PN。先做原文标准化和精确匹配，再应用客户确认的命名规则。

视为同一料号：

- 忽略 `-`、`_`、`/`、`.` 等分隔符。
- 忽略料号开头或结尾的零。
- 忽略示例形式的版本后缀差异，例如 `ABC001-01` 与 `ABC001-02`。
- 全角字符转为半角，并删除空格、换行等空白字符。
- 去除 Excel 数字显示产生的 `.0`。

视为不同料号：

- 不删除客户或品牌前缀。
- 不把 O/0、I/1 等字母和数字自动替换。
- 没有明确映射时，不自动关联新旧料号。

安全约束：

- 原文精确匹配优先，即使该料号所在的归一分组存在字段冲突，也使用精确对应行。
- 非精确匹配时，归一分组内所有候选的商品名称、商品编号和品牌必须一致，才能自动使用。
- 候选字段不一致时标红并留空，不根据行顺序任意选择。
- 不进行编辑距离、包含关系等其他宽松模糊匹配。

## 合并规则

1. 按用户上传文件的顺序处理源报表，各文件内部保持原明细顺序。
2. 只保留数量大于 0 或金额大于 0 的明细。
3. 金额为空或为 0、但数量和单价均有效时，使用 `数量 × 单价`。
4. 不按料号跨文件汇总；每条有效源明细生成一条输出明细。
5. `Serial No.`、提货日期、Ship to、运输方式从各自源报表提取。
6. 商品名称及规格型号、商品编号必须来自规则文件，不采用源报表中可能存在的同名中文列。
7. 规则文件存在多个候选工作表时，按表头完整度、料号唯一性和有效记录数选择。
8. 选中的规则工作表内出现重复料号且映射冲突时，采用后出现的记录并产生警告。
9. 输出字段顺序由模板表头决定；当前支持字段见 `src/report_merge/template.py` 的 `FIELD_ALIASES`。

## 异常处理

阻止生成：

- 文件数量为 0 或超过 30。
- 文件不存在或扩展名不支持。
- 源报表找不到必要明细表头。
- 模板找不到可识别的输出表头。
- 规则文件找不到可用映射表。
- 输出路径覆盖源文件、模板或规则文件。
- 选择 `block` 策略后仍有未匹配料号。

允许生成但警告：

- 使用料号命名规则完成非原文精确匹配。
- 归一后存在多个商品字段冲突的候选规则。
- 规则完全未匹配：默认输出空的商品名称/商品编号，并标红。
- 模板含未支持列：保留列名但不填值。
- 规则文件内同一料号存在冲突。

预览确认：

- 精确匹配正常显示。
- 命名规则匹配以黄色显示，并列出匹配规则和目标规则料号。
- 完全未匹配或归一后规则冲突以红色显示。
- 存在任何黄色或红色提醒时，页面要求用户勾选确认，服务端生成接口也要求显式确认。

## 输出文件

- 格式：`.xlsx`。
- 使用客户模板中识别出的工作表和表头顺序。
- 清除模板表头以下的样例数据，再写入合并结果。
- 料号、项号、商品编号和 Serial No. 以文本格式写入，避免丢失前导零。
- 命名规则匹配的规则字段使用黄色填充；完全未匹配或规则冲突使用红色填充。
- 生成后重新打开工作簿做基本结构验证。

## 配置与历史

- 不区分管理员和普通用户，页面可直接上传当前模板或规则。
- 新配置上传后先做结构验证，验证成功才替换当前配置。
- 每次配置更新保留一份本地版本副本。
- 每次成功预览即创建历史记录。
- 每条历史记录保存源报表、该次实际使用的模板和规则、预览 JSON 以及生成后的结果。
- 即使当前模板或规则后来更新，旧历史记录仍可还原当时输入和配置。
- 删除历史记录时，同时删除该记录对应的本地文件。
